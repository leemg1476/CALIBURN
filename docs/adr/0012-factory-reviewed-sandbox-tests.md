# ADR 0012 — Separately reviewed Factory sandbox tests

Status: accepted for opt-in development Python stdlib tool tests. Not production activation or complete Factory qualification.

The Factory already stores inert bundles and independent incomplete static reports. Neither constitutes permission to execute source. Repository patch approvals must not authorize unrelated Factory bundles. This increment implements a concrete request → independent decision → runtime resume → isolated tests → durable execution evidence consumer.

Migration0007 adds six tables: factory_exec_roles, factory_exec_plans, factory_exec_requests, factory_exec_decisions, factory_exec_revocations and factory_exec_jobs. Plans are operator-owned, immutable and scoped to one candidate/static report/test bundle/image/expiry. Plans accept only tool-kind candidates with no declared dependency installation or requested permissions, whose current independent static report is REVIEW_REQUIRED. BLOCKED source, MCP/Skill artifacts and dependency/permission requests remain ineligible. Static triage is still incomplete; independent review is mandatory.

New tasks need a separate default-off CALIBURN_ALLOW_FACTORY_EXECUTION grant. Typed capability_request_execution(plan_ref) persists a binding of Task/principal/tenant, bundle/source/static report/test plan/image/implementation hashes and limits, then ends its Run in WAITING_APPROVAL. Replaying a receipt cannot substitute another plan. General pause/resume APIs cannot approve a wait. capability_execute_tests accepts only the exact approved request reference, never commands/images/source/permission flags.

An operator maps preprovisioned PostgreSQL roles separately as REVIEWER or EXECUTOR. They receive no Task/candidate mutation rights. The reviewer cannot be source/request/plan author or static report author and cannot represent the Task actor. It only appends a hash-bound expiring decision/revocation; the runtime worker wakes actionable approved waits using its own Task authority. A bounded actionable/latest-request query avoids starvation from unrelated/pending waits. Repository reviewer and static verifier mappings confer no Factory execution authority. Runtime cannot configure roles/plans, append decisions/revocations, claim executor leases or fabricate execution evidence. PostgreSQL guards add independent scope/author/transition/fencing checks; the owner/admin schema boundary remains trusted.

A separate trusted-host supervisor with an EXECUTOR connection uses the existing immutable reviewed-test image and fixed unittest driver. No Docker module/process capability is added to runtime agents. No new image or dependency is built. It independently inspects container limits before source delivery and rechecks current approval/role/expiry/task/hash/image admission immediately before delivery, while running and before publication. Wrong-image supervisors leave other-image jobs queued. Controller claims are fenced, bounded to at most3 and the Task retry cap, with immutable terminal results. Review/source/plan changes require a new binding/decision. Revocation/disablement/cancellation cause fail-closed polling and container cleanup. Source may have started before an interrupted/lost dispatch, so absence of a result is not proof that source never ran.

The candidate's generated tests, an operator's independent test bundle and a fixed strict fixture-comparison test form the exact reviewed plan. The framework imports the declared Python callable inside the isolated child and invokes it with fixture keyword arguments, comparing types/values recursively. The existing driver enforces network-none, nonroot UID10001, read-only root, no mounts/socket/secrets, cap-drop/no-new-privileges/seccomp,128MiB/.5CPU/PID32,16MiB tmpfs and bounded file/CPU/wall/output resources. It returns actual exit/status/bounded untrusted output and source/plan hashes; the host binds these to request/image/executor identity. Completion means a test observation, not a successful test or activation.

Evidence remains security INCOMPLETE, license UNREVIEWED and production_approved=false, including PASSED cases. Generated tests and fixtures are proposals reviewed by the operator/reviewer; they are not independently discovered correctness specifications. A malicious approved Python test/subject can tamper with its child process/test framework or exit; passing logs/exit code are not anti-tamper behavioral certification. Full property/negative/replay/poison/SAST/dependency/license qualification, MCP/Skill/nonstdlib adapters, signing, registry activation and measured invocation reuse remain required future work.

Results persist independently of the runtime tool checkpoint. An actual worker process death after reading a completed result is recovered by a replacement worker without redispatch, while cumulative tool attempts remain charged. Data/test/Git supervisors use different durable queues and cannot consume Factory jobs. Default/API permissions remain unchanged; no live role/grant/customer deployment is enabled by adding this code.

Rollout requires head0007 and drained/canceled incompatible digest-pinned tasks. Disable the server flag to stop new grants; disable/revoke roles/requests to stop active admission. Mapping disablement is an authorization check, not DB credential/SELECT-grant revocation; operator credential offboarding is separate. Prefer application rollback retaining evidence. Explicit backup/operator approval is required for downgrade to0006: it destroys only Factory execution roles/plans/requests/decisions/revocations/jobs, retaining candidates/static reports/runtime history. Preprovisioned DB roles need separate offboarding. No license/branding assumptions changed and the separate Git-image approval remains pending.

Additional security evidence: a caller-created temporary factory_exec_roles table restored a disabled reviewer in a pre-hardening negative test. Migration0007 fixes13 Runtime/Policy/Factory trigger lookup paths using the trusted schema and explicit pg_temp last, preserving implicit pg_catalog-first lookup and invoker current_user. Regression attacks against Factory execution/static and repository review are denied. No SECURITY DEFINER or expanded privilege was introduced; this shared hardening remains on downgrade to0006.
