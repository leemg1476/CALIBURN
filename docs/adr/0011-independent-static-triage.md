# ADR 0011 — Independent inert Factory triage evidence

Status: accepted for static triage only; generated execution and activation remain closed.

Proposal checks were produced in the authoring service and could not provide independent provenance. Add an actual durable consumer before executable qualification: an explicitly granted `capability_check` creates a bounded request and waits; a separate configured PostgreSQL verifier role/process produces an immutable report; the original runtime worker receives the hash-bound result. No candidate source is imported or executed.

Migration0006 adds factory_check_jobs, factory_check_reports and factory_verifiers. Job input/identity/digests/deadline are immutable. A unique Step receipt prevents duplicate requests on checkpoint recovery. SKIP LOCKED leases fence concurrent/crashed verifiers; at most3 claims occur, and task/call budgets bound waiting. Reports and FINISHED job state commit atomically. Runtime roles get request INSERT/read only, not report INSERT/job UPDATE/verifier provisioning. A mapped verifier receives narrow queue-column/report rights, no runtime Task writes or candidate mutations. Recheck mapping enablement, tenant, source/request author separation, runtime mutation privileges, source/checker hashes and task deadline/state before publication. DB triggers independently reject forged source/activation/security-success fields, stale leases, source scope changes and report mutation.

The independently provisioned role must be separate from the candidate/request author, cannot mutate runtime Tasks/candidates and is not automatically inherited from repository review authority. Only a schema owner/operator may configure/disable an existing role; the model/API cannot provision it. Tests use synthetic NOLOGIN roles, not human identity or cryptographic attestation. Direct verifier DB access remains trusted; there is no customer RLS/OIDC isolation or permission for untrusted roles to use arbitrary SQL. Existing owner/admin controls remain trusted schema boundaries.

The checker validates the bounded bundle, parses Python AST and flags selected sensitive imports/dynamic/IO calls, syntax errors, dunder access and instruction-override text patterns. Permission/dependency declarations require further review. The finite heuristic can miss obfuscated behavior and flag benign code; it is triage, not complete SAST, secret discovery, dependency audit or prompt-injection certification. No candidate tests, fixtures' behavior, MCP server or skill instructions execute. An unflagged artifact is REVIEW_REQUIRED, never PASS. Security remains INCOMPLETE, execution NOT_RUN, dependencies UNVERIFIED, license UNREVIEWED and activation_eligible=false. Flagged artifacts are BLOCKED; no state can activate a candidate.

The checker/authority/contracts/schema/orchestrator implementation digest is pinned with the bundle digest and report hash. Changing implementation invalidates existing granted task policy rather than silently moving it to a new checker. The source bundle stays QUARANTINED; immutable proposal-local checks remain historical and are not overwritten by independent reports. Report lookup is an authenticated scoped endpoint.

Paused work is excluded from claim selection so it does not starve runnable requests. A resumed task reuses its pending Step/request; terminal/deadline-ended requests are canceled by the verifier, while offboarding makes publication fail closed. Verifier crashes leave leased metadata that another admitted verifier can recover. There are no external effects or containers to leak in this phase. Report publication checks visible Task state at the statement boundary; this is not a distributed execution cancellation protocol. API/worker polling performs its own current-owner check before consuming/committing results.

Rollout is default-off via CALIBURN_ALLOW_CAPABILITY_CHECKS, independent of proposal grants. New tasks only; old policies do not gain it. No new dependency/image/license/branding assumption. Application rollback should retain schema/evidence and stop/drain granted tasks. Explicit backup plus operator approval is required before downgrade0006 to0005, which deletes requests/reports/verifier mappings. Table grants disappear with dropped tables; operator-managed roles/credentials need separate offboarding. Live/source execution review, sandbox behavior/security testing, signing, active registry and qualified cross-task invocation remain future requirements.
