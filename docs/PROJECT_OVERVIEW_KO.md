# CALIBURN 프로젝트 한눈에 보기

## 한 문장 정의

**요청을 스스로 수행하고, 필요한 실행 능력을 직접 만들어 검증·축적하며, 기업 권한 안에서 장기간 안정적으로 일하는 범용 자율 에이전트 플랫폼.**

## 기존 챗봇/에이전트와의 차이

| 비교 항목 | 일반 챗봇 + Tool Calling | CALIBURN 목표 |
| --- | --- | --- |
| 작업 단위 | 한 번의 대화/응답 | 재개·취소·검증 가능한 장기 Task |
| 실행 방식 | 정해진 함수 호출 | 계획 → 실행 → 검증 → 보완 반복 |
| 없는 기능 | 사람이 개발해 추가 | 후보 Tool/MCP/Skill 자동 생성 → 독립 검증 → 승인 → 재사용 |
| 기억 | 대화 요약/벡터 검색 | 사실·결정·교훈·Skill 구분, 정규화·중복/충돌 판정·평가·만료 |
| 인증 | API Key를 Tool에 직접 전달하기 쉬움 | 사용자·Task·Tool 버전별 위임 권한과 단기 비밀 주입 |
| 운영 | 응답/호출 로그 위주 | 근거·아티팩트·실행 이력·회귀 실패·권한 결정을 추적 |
| LLM | 특정 벤더 중심 | 로컬/상용 혼합, 고객별 데이터 반출 정책 |
| 대외 판매 | 소스 라이선스/운영 제약 | UI 라이선스 경계 분리, 온프레미스/사설망 패키징 |

## 최우선 구현 원칙

1. **작업을 영속화한다.** 웹 연결이 끊기거나 워커가 재시작돼도 Task 상태와 근거가 남아야 한다.
2. **모델과 실행 권한을 분리한다.** 모델은 요청하되, 권한 부여·인증·실행은 별도 정책 엔진/런타임이 수행한다.
3. **한 번 만든 능력을 재검증하며 사용한다.** Tool Factory는 자동 코드 생성기가 아니라 검증된 실행 능력의 공급망이다.
4. **기억에 들어가기 전 정제한다.** 발생한 일과 검증된 교훈을 구분한다. 충돌·범위·유효기간을 관리한다.
5. **상용화 가능성을 처음부터 확보한다.** Open WebUI는 분리된 UI 통합 대상이다. 최신 버전의 브랜드 제한을 무시하고 CALIBURN으로 덮어씌우면 안 된다.

## 실제 배포 후 기대하는 세 가지 대표 장면

### 1. 개발 자동화

“이 저장소의 GitLab CI 배포 실패 원인을 찾아 고쳐줘”라고 요청한다. 시스템은 저장소와 로그를 확인하고, 변경 후보를 만들고, 격리 테스트와 차이 보고서를 생성한다. 승인 이후에만 PR을 올린다.

### 2. 새로운 능력 획득

프로젝트를 처리하다 특정 내부 API용 MCP가 없다면, 새 서버를 작성·검증해 제안한다. 테스트·보안·라이선스·권한 검토를 통과한 버전만 등록한다. 다음 번엔 동일 기능을 재개발하지 않고 해당 버전을 재사용한다.

### 3. 고객사 인증이 필요한 업무

사용자는 필요한 GitLab/사내 API 권한을 위임한다. LLM에는 비밀번호를 보여주지 않고, 인증 브로커가 해당 작업·해당 도구·해당 자원에만 유효한 단기 토큰을 주입한다. 작업을 취소하거나 위임을 회수하면 다음 호출부터 차단된다.

## 초기 코드의 정확한 수준 (M0 초기 반입 시점; 하단 M1 갱신 참고)

현재 포함된 코드는 **M0 개발 시작점**이다. 테스트용 챗 UI API, 안전한 정적 도구 호출 루프, 로컬/상용 OpenAI 호환 엔드포인트 연결용 어댑터, SQLite 작업 메타데이터 저장을 제공한다. **아직** Codex 수준의 자율 코딩, 작업 재개, 임의 코드 실행 샌드박스, Tool Factory, Vault/OIDC 통합이 구현된 것은 아니다.

실제 구현 순서는 `IMPLEMENTATION_PLAN.md`, 보안·라이선스는 `SECURITY.md`와 `LICENSING_AND_IP.md`, Codex 첫 지시는 `../prompts/CODEX_START.md`를 확인한다.

## 구현 현황 갱신 — 2026-11-08

초기 코드 설명 이후 M1 백엔드가 추가됐다. PostgreSQL 영속 큐, 독립 비동기 워커, lease/heartbeat와 오래된 워커 차단, 단계 체크포인트, 프로세스 장애 복구, 중단·취소·재개, 호출·시간·토큰·비용 예약 한도, SSE 재접속, durable OpenAI 모델 어댑터를 실제 실행으로 검증했다. 추론은 fixture이며 실제 LLM 품질을 검증한 것은 아니다. Open WebUI 브라우저, 코딩 샌드박스, Tool Factory, OIDC/Vault와 검증 기억은 아직 구현 전이다. 최신 실행 절차·한계는 M1_RUNTIME.md, 진행·증거는 DEV_PROGRESS.md를 따른다.

## M2 데이터 작업 슬라이스 갱신

격리 컨테이너에서 저장소 스냅샷의 목록·검색·읽기와 비실행 후보 패치를 처리하는 경로를 실제 워커에 연결했다. 스냅샷은 서버 측 범위·만료·회수 권한과 해시로 고정되며, 기존 로컬 Git 커밋에서 명시한 파일만 읽는 운영자 import를 지원한다. API·워커에는 Docker나 호스트 명령 권한을 추가하지 않았다. 후보는 승인·실행되지 않으며, 실제 checkout·테스트·수정 검증 루프와 기업용 승인·인증은 아직 남아 있다. 실행 증거는 `evidence/m2-workspace-demo.json`, 범위와 절차는 M2_WORKSPACES.md를 따른다.

## UI·장애 정리 검증 갱신

원본 브랜딩을 유지한 Open WebUI v0.13.0 화면에서 실제 durable Task 요청과 응답 42를 확인했고 PostgreSQL 작업·이벤트 기록과 대조했다. 추론은 fixture이며 기업 인증·작업 타임라인·실제 모델 품질의 증거는 아니다. 초기 스트림 프레임 뒤 연결을 끊어도 워커가 작업을 완료하는 실제 HTTP 검증과, 지연 생성된 컨테이너의 취소·재시작 정리 회귀 검증을 추가했다. 후보 코드 승인 실행은 아직 열지 않았다. 상세는 OPEN_WEBUI_SMOKE.md와 ADR 0003을 따른다.
